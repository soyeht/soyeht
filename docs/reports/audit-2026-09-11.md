# Architecture and single-source-of-truth audit · 2026-09-11

Scope: `main` at 0c0092e (end of slice 1, middle of slice 2). Read-only
review of the engine workspace, the contract generator, the Swift clients,
the scripts and the docs. Every claim points at a file and line. Items are
ordered by importance inside each list.

## What is right
1. **One protocol source, generated and checked.** `contracts/generate.py:166-192`
   emits Rust, Swift and TypeScript from `contracts/protocol.json`; every
   generated file carries the schema sha256 (`engine/soyeht-protocol/src/generated.rs:1`,
   `contracts/swift/Sources/SoyehtProtocol/Generated.swift:1`,
   `contracts/typescript/src/generated.ts:1`); `generate.py --check` runs in
   the gate (`scripts/check_all.sh:13`). Requests are validated against the
   embedded schema, not against structs (`engine/soyeht-protocol/src/validate.rs:12-19`).
2. **Shared test vectors** consumed by the three runtimes
   (`engine/soyeht-protocol/tests/vectors.rs:41`, `contracts/swift/Sources/ProtocolVectors/main.swift:14`,
   `contracts/typescript/test/messages.test.ts:6`), with one vector per
   method and event enforced by `contracts/test_generator.py:23-35`.
3. **Crate graph without cycles**; `soyeht-protocol` is a leaf; `soyeht-ptyd`
   knows nothing about workspaces (grep empty). Mac and iPhone apps are thin
   UI over `SoyehtClient` (`apps/ios/Sources/PhoneModel.swift` delegates
   everything); the Swift client uses the generated types, never retypes them
   (`apps/shared/Package.swift:13-15`, `EngineClient.swift:7-9`).
4. **Real acceptances**: e2e under launchd with the production plists
   (`scripts/e2e.py:163,183`); SQLite tests on a real database
   (`engine/soyeht-store/tests/storage.rs`, `agents.rs`); a real ACP test peer
   process (`engine/soyeht-acp/tests/fake_protocol.rs`). No test reimplements
   the code it tests.
5. **Discipline where it matters**: `unsafe` blocks all carry SAFETY comments
   under `deny` lints (`engine/Cargo.toml:32-36`); the operation log keeps an
   allowlist of methods so secrets never reach it (`engine/soyeht-engine/src/server.rs:301-311`);
   the local gate `scripts/check_all.sh` runs every step the workflows ran.
6. The 20 ADRs match the code; none is contradicted.

## What must be fixed (engine)
1. **Business rules write raw SQL, bypassing the store.** Eight engine files
   embed SQL (`engine/soyeht-engine/src/input.rs:31,50`, `model.rs:109`,
   `dispatch.rs:84,184,309`, `core.rs:186`). `soyeht-store` is half a
   persistence layer. Fix: every query moves behind a function in
   `soyeht-store`; the engine never imports `rusqlite`. Add a gate check that
   fails when `rusqlite` appears in `soyeht-engine/Cargo.toml`.
2. **No abstraction boundary at all: zero traits in the workspace.** Rules
   depend on concrete IO, so they cannot be tested without a database or a
   socket. Fix: one trait per IO port the rules use (store, supervisor
   client, clock), with the real implementation and a test double.
3. **98 `unwrap`/`expect` in engine `src`**, some on the path that serves
   snapshots to clients (`engine/soyeht-engine/src/dispatch.rs:257,283-288`).
   Fix: `clippy::unwrap_used` and `clippy::expect_used` as `deny` outside
   tests; convert to typed errors.
4. **Errors are inconsistent across crates**: a proper enum in the store
   (`engine/soyeht-store/src/database.rs:12`), a `String` newtype in ACP
   (`engine/soyeht-acp/src/rpc.rs:14`), `io::Error::other("text")` in ptyd and
   CLI (`engine/soyeht-ptyd/src/client.rs:36-46`). Fix: one error enum per
   crate with named variants; the wire mapping to `ErrorKind` lives in one
   place.
5. **Limits expressed as arithmetic on a constant with another meaning.**
   ADR 0020's outbox and checkpoint limits appear as
   `16 * limits::JSON_BYTES` and `count >= 128 || ... CONNECTION_QUEUE_BYTES`
   (`engine/soyeht-store/src/agents.rs:81,144,315`); `JSON_BYTES / 2` is
   repeated three times (`engine/soyeht-acp/src/config.rs:56,160`,
   `agents.rs:308`). Fix: named limits in `contracts/protocol.json` `x-limits`
   so they are generated into `limits.rs`.
6. **Orphan code**: `soyeht-acp` (730 lines) has no dependent crate and
   `soyeht-store/src/agents.rs` (458 lines) has no production caller. Planned
   by ADRs 0019 and 0020 as "next step"; it must be wired in slice 2 or the
   crate is dead weight that compiles and passes tests without ever running
   integrated.
7. **Duplicated code**: frame reading in `engine/soyeht-cli/src/lib.rs:46-54`
   and `engine/soyeht-ptyd/src/client.rs:42-48`; two independent NDJSON
   decoders for the same ACP stream (`engine/soyeht-ptyd/src/pending.rs:19-41`
   and `engine/soyeht-acp/src/rpc.rs:115-169`). Fix: one shared reader in
   `soyeht-protocol`.
8. **One 242-line function** in the component that forks processes
   (`engine/soyeht-ptyd/src/server.rs:182`, `fn execute`). Fix: one function
   per request kind.

## What must be fixed (contracts, clients, docs)
9. **Dev profile has no single source.** The data path
   `Soyeht.next/dev` is typed in three languages
   (`scripts/install_dev.py:13`, `apps/shared/Sources/SoyehtClient/Profile.swift:4-5`,
   `engine/soyeht-cli/src/main.rs:16`, `engine/soyeht-ptyd/src/main.rs:16`,
   `engine/soyeht-engine/src/main.rs:9`); port 8291 is a literal in
   `engine/soyeht-engine/src/main.rs:33,35` and `core.rs:51`; launchd labels
   are assembled by string in `scripts/install_dev.py:26,42` and
   `scripts/e2e.py:154,163`. Fix: a `profiles` block in `contracts/protocol.json`
   (or a sibling `contracts/profiles.json`) generated into Rust, Swift and
   Python like the limits.
10. **Events have no generated registry.** `generate.py:174` emits a
    `Methods` table only; the 37 event names are hand-typed strings in
    `apps/shared/Sources/SoyehtClient/EngineClient.swift:233-279`, so renaming
    an event breaks nothing at compile time. Fix: generate an `Events`
    table (Swift enum, TS const, Rust enum) and dispatch on it.
11. **An error kind outside the contract**: `"engine_identity_changed"` in
    `apps/shared/Sources/SoyehtClient/EngineClient.swift:59` and
    `DeviceIdentity.swift:67` does not exist in `x-errorCodes`. Fix: add it
    to the schema or map to an existing kind.
12. **Duplicated Swift**: `MacTerminal.swift:43-55` and `PhoneTerminal.swift:31-43`
    are the same resize and revision algorithm, with the same delegate stubs
    and palette. Fix: one shared terminal host in `SoyehtClient` with two
    thin platform wrappers. The pairing decision panel appears twice in
    `apps/mac/Sources/WorkspaceWindow.swift:172-181,215-222`.
13. **Docs that contradict the code**: `docs/reports/slice-1.md:14` says
    "26 methods and 22 events" (the schema has 39 and 37); `README.md:28`
    describes `apps/desktop/` (only a `.gitkeep` exists) and an MCP server
    crate that does not exist; `docs/apps-iphone.md:26` says the app "does
    not participate in this build" while `scripts/check_ios.sh:18` builds it.
    ADRs 0007–0020 carry no date. Fix in the same PR that touches each.
14. **The design file** `design/soyeht-desktop.pen` is tracked (875 KB) and
    contains mock text in Portuguese and a local path (`:14538`). Decide:
    keep the mock text as design-only exception, or scrub the path and move
    the file out of the repo. Rule already agreed: the file is edited by one
    person only.

## Process rules taken from the 2026 literature on agent-maintained repositories
- **Contract drift review**: every agent PR lists changes to error kinds,
  input validation and fallbacks; the reviewer checks them first (the
  strongest predictor of later failures in the CodeThread study).
- **Short rules file, no repository overview**: rules, commands and a
  "task → document" table; overviews measurably do not help and cost tokens.
- **One short document per subsystem** with "how it is tested" and "what
  never to do here", kept next to the code.
- **Tests named by behaviour**, usable as examples of intended use.
- **A stale spec is worse than none**: contract, ADR or report contradicted
  by code is fixed in the same PR.
